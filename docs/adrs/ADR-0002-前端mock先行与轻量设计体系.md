# ADR-0002: 前端 mock 先行策略与轻量设计体系

状态：accepted（依据用户 2026-10-14 明确要求：前端搭建与模拟数据打通、暂不接后端真实数据、紧凑信息密度、政务适配基调）

## 背景

什么真实需求、约束或冲突要求此决策？本阶段要求把 SignalFlow 前端从入口开始按业务需求与功能切片推进，用**模拟数据**跑通全流程展示；后端真实数据与 LLM 洞察尚未就绪。同时用户要求前端设计紧凑、信息密度合理、不堆砌展板，体现"客户反馈决策工具"理念，并适配政务系统（数据不出域、可私有化）。存在两个真实分歧点：(1) 数据来源——等后端 vs mock 先行；(2) 样式实现——引入重组件库 vs 轻量自研。

## 考虑的方案

| 方案 | 对本需求的适配度 | 成本或风险 | 证据 |
| --- | --- | --- | --- |
| Mock 数据先行 + 适配层切换（采用） | 高：前端可独立开发与演示，类型契约与后端对齐，后续零改动切换 | 需维护 mock 数据与契约同步纪律 | 用户明确要求；Canny/PingCode 等产品先 UI 后链路的实践 |
| 等待后端就绪再开发前端 | 低：本阶段无法交付任何可见结果，与用户目标冲突 | 阻塞整体进度 | 不采用 |
| 引入 Ant Design Vue / Element Plus / Naive UI | 中：组件丰富但引入重依赖与设计风格约束 | 需额外学习与主题定制；政务内网构建产物变大；风格需大量覆盖才符合品牌 | 仅后端骨架依赖已验证，前端组件库未确认 |
| 轻量自研组件 + CSS 变量设计 Token（采用） | 高：完全掌控紧凑密度与政务稳重风格，无外部依赖，本地化资源 | 自研组件需维护；复杂组件（表格/图表）需在首版做足 | Ant Design token 体系、vue-vben-admin CSS 变量主题、frontend-design 方法论 |
| 外部 webfont / CDN 图表库 | 低：政务内网可能无外网 | 字体/图标/统计脚本不可达导致页面异常 | 政务"数据不出域"约束 |

## 决策

- **数据层**：前端建立 `src/api` 适配层 + `src/mocks` mock 数据源，通过 `VITE_USE_MOCK` 环境变量切换；本阶段默认 mock，后端就绪后设 `VITE_USE_MOCK=false` 即可切换真实 HTTP，页面与 store 代码零改动。类型契约以 `src/types/index.ts` 为唯一口径，与 `backend/app/schemas` 保持同步。
- **样式体系**：轻量自研组件（按钮/卡片/表格/抽屉/徽标/图表基础件）+ CSS 变量设计 Token（明暗双主题），不引入重量级组件库；视觉基调为"工业克制 + 编辑式排版"，主色海军蓝系（见 `docs/frontend-development-plan.md` §5）。
- **规范载体**：设计规范（色调/密度/布局）、业务切片、推进秩序、前后端衔接流程写入 `docs/frontend-development-plan.md`，作为本阶段及后续实现的唯一规范源。
- **功能范围**：FS-0 应用壳 → FS-1 总览 → FS-2 反馈管理 → FS-3 洞察决策 → FS-4 路线图任务 → FS-5 回复回传，加 FS-6 政务最小页与 FS-7 设置最小页；每切片按该文档 §3.3 独立验收。

## 后果与所有权

- 收益：前端可独立交付可演示闭环；政务适配风格在一开始就固化；无重依赖，构建产物本地化完成"数据不出域"基础。
- 成本或新风险：自研组件投入高于直接用组件库；mock 与后端契约可能漂移，需靠类型校验纪律约束；图表功能首版以轻量 SVG/CSS 为主，复杂图表需求可能触发组件库 ADR。
- 项目自身仍需拥有：设计 Token 定义、紧凑密度规则、mock 数据维护、契约同步检查；这些不因轻量自研而外包。
- 迁移、回滚或退出条件：若某页面复杂度使自研成本失控，可按组件维度引入成熟组件库（先出 ADR）；若后端契约变更，仅需同步 `src/types` 与 mock 数据即可回归。

## 置信度与重访触发

- 置信度：高——mock 先行与用户目标直接匹配；轻量自研在政务私有化约束下风险可控。
- 重访时机：后端契约落地后（验证 mock 切换机制）；出现"表格/图表/表单复杂度显著超出自研能力"的实际证据时；用户确认组件库选型时。
