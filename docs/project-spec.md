## 目标与用户

- 用户与背景：面向产品、客服与客户成功团队的客户反馈决策工具；政务版本面向政务系统诉求处理场景。
- 待解决问题：客户声音散落在工单、销售记录、访谈纪要、应用商店评论等多个渠道；反馈分散、重复难去重、优先级依赖"谁嗓门大"、决策后缺乏对客户的闭环回传；反馈处理回传时缺少交叉销售/政策告知的机会识别。
- 成功且用户可见的结果：从多渠道收集反馈 → AI 去重聚类并归纳痛点 → 结合客户影响评估排出有依据的优先级 → 形成路线图与产品任务 → 自动起草客户回复并回传状态，形成完整闭环；产品经理始终保留最终决策权（AI 辅助决策，不做自动决策）。

## 主流程

1. 触发与输入：来自客服工单、销售记录、访谈纪要、应用商店/政务热线等渠道的反馈，通过渠道适配器接入。
2. 重要处理与决策：Embedding 相似度去重合并 → 语义聚类与主题归纳 → 痛点识别 → 客户影响面/受益人群评估 → 优先级评分（RICE 思想）→ 候选+置信度辅助决策 → 生成产品任务/回复草稿。
3. 存储事实与状态变化：反馈原文（保留原话）、去重与聚类结果、主题与痛点的结构化数据、影响评估与优先级评分、路线图项目、产品任务、回传状态。
4. 用户可检查的输出或产物：洞察看板（主题/趋势/预警）、可解释的优先级打分卡、路线图、产品任务、客户回复草稿与回传记录；政务版含诉求分级分类、督办分级、审计留痕与政策告知。

## 组件与所有权

| 组件或边界 | 拥有 | 接收 | 产出 | 不得做 |
| --- | --- | --- | --- | --- |
| 渠道适配层 | 各渠道的接入、解析与规范化 | 工单/评论/访谈/政务热线原始数据 | 规范化反馈事件 | 篡改反馈原话 |
| API 层 | 对外接口契约、权限、审计 | 前端/外部调用 | REST/异步任务接口 | 绕过服务层直达持久化 |
| 服务层（业务） | 业务流程编排、影响评估、优先级 | API 层调用 | 可解释的评估结果 | 混入 LLM 细节 |
| AI 工作流（LangGraph） | 去重、聚类、痛点归纳、草稿生成的有状态编排 | 规范化反馈与评估上下文 | 洞察、置信度、草稿 | 单模型固化、替代人工决策 |
| LLM 网关（LiteLLM） | 多模型接入、密钥、降级 | AI 工作流 | 统一 LLM 调用与限流/降级 | 把模型差异泄漏到上层 |
| 持久化层 | 反馈、聚类、任务、回传状态与审计 | 服务层 | 可查询、可追溯的数据 | 保存未脱敏的密钥/敏感凭证 |

## 输入、输出、状态与错误规则

- 输入与校验：渠道解析后的反馈须通过 schema 校验；无效/重复输入按幂等策略处理。
- 输出与产物：洞察看板数据、打分卡、路线图、任务、回复草稿、回传记录；全部可追溯至原始反馈。
- 权威状态与所有权：反馈、聚类、任务与回传状态以持久化层为准；UI/缓存/通知只是视图。
- 错误、超时、重试、重复、重启与权限行为：LLM 调用超时/失败须可降级（如候选模型切换或跳过 AI 步骤保留人工通道）；渠道接入须幂等；政务版须留痕可审。
- 安全、隐私、性能与成本约束：密钥仅存环境变量/密钥管理；反馈原文可能含敏感信息需脱敏策略；政务版要求数据不出域、可私有化部署；LLM 成本受调用频率与 token 预算约束。

## 技术关注点与候选边界

- 相关运行时、设备、部署或执行边界：Python 后端（FastAPI）+ Web 前端；容器化部署（Docker）; 支持私有化。
- 数据、状态、外部系统与权限边界：反馈/洞察/任务数据存储；向量库承载去重与聚类；LLM 服务为外部依赖。
- 需要公开研究的技术问题：LangGraph 工作流最佳实践、LiteLLM 网关配置、pgvector 聚类方案（后续按真实需求再研究）。
- 候选方案及其所有权边界：见 `docs/adrs/ADR-0001-总体技术选型.md`。
- 已接受决策及其 ADR：总体分层架构、Python + FastAPI + LangGraph + LiteLLM + Docker + GitHub Actions（ADR-0001）。

## 验收原则

- 用户或受支持系统边界必须能观察到：反馈从渠道进入后经去重/聚类/评估形成可查看的洞察与决策依据；产品经理可作出决策并生成任务与回复草稿；回传状态可追踪；政务版分级/督办/审计规则可运行。
- 单一测试命令不足以构成验收原则，须匹配边界证据（API/持久化检查、浏览器可见检查等）。

## 非目标

- 本骨架阶段不实现完整业务功能；仅搭建分层框架与基础设施（不做全量功能实现）。
- 不做自动决策替代产品经理；AI 仅产出候选与置信度。
- 不接入真实生产渠道与生产 LLM 密钥（开发阶段使用样例与本地/测试模型）。

## 开放问题

- 前端框架最终选型是否锁定 Vue 3 / TypeScript（骨架已按该方向预留，待用户确认）。

- 政务版合规细节：数据密级分类、审批流程的具体规则待业务确认。
